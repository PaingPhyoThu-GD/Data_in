## ducklake_medallion_prototype.md

*   **Status endpoint & `ManifestState` omit per-entity Quality Gate summary**: `ManifestState` (`src/ducklake/models.py`) adds `latest_status: Optional[QualityStatus] = None` (populated in `src/ducklake/service.py`), which is not in the spec's `ManifestState` schema, and `GET /api/lakehouse/status` (`frontend/lakehouse_routes.py`) returns `ManifestState` without the `QualityGateResult` / per-check summary (`checks`, `entity_statuses`) described in the design. Correspondingly, the UI's Quality Gate & Quarantine panel (`frontend/static/lakehouse.js`) only renders the overall badge and Quarantine table rather than individual rule/entity assertion statuses.
*   **`runs_history.jsonl` serializes `"rule_id"` instead of `"_rule_id"`**: `QualityCheckResult` defines `rule_id: str = Field(..., alias="_rule_id")` with `populate_by_name=True` (`src/ducklake/models.py`), and `LakehouseService._append_run_history` calls `report.model_dump_json()` without `by_alias=True` (`src/ducklake/service.py`), persisting `"rule_id"` rather than the specified `"_rule_id"` field name in `runs_history.jsonl`.
*   **Adapter streaming helper names & `"data"` unwrapping placement**: `src/ducklake/adapters/base.py` exposes public `iter_jsonl_records` and `iter_landing_records` instead of the specified `_iter_jsonl_records` and `_iter_landing_records`. In addition, `iter_landing_records` yields raw JSON dicts directly instead of centrally unwrapping `record.get("data", record)`; each non-telemetry adapter handles `"data"` unwrapping individually, while `src/ducklake/adapters/telemetry.py` unwraps `recent_events` or raw event dicts without checking `"data"`.
*   **`youtube_channels` lacks Quality Gate rules while remaining in Quarantine filter lists**: The design pairs `youtube_channels` / `youtube_videos` under `YT_NEGATIVE_DURATION` and `YT_NEGATIVE_VIEWS`, whereas `src/ducklake/quality.py` puts `youtube_channels` in `PASSTHROUGH_ENTITIES` and enforces those two rules only on `youtube_videos`. Meanwhile, `QUARANTINE_ENTITIES` (`src/ducklake/models.py`) and `#ducklakeQuarantineEntity` (`frontend/static/index.html`) still list `youtube_channels`.
*   **Silver Parquet write ownership, NULL `order_id` dedup, schema gate checks, and NULL rule predicates**:
    *   `src/ducklake/silver.py` creates only `:memory:` TEMP tables; `DuckDBSQLQualityGate.evaluate_and_materialize` (`src/ducklake/quality.py`) performs all Silver Parquet `COPY` materializations.
    *   `silver_sales_orders` deduplicates on `COALESCE(order_id, '__null__' || CAST(rowid AS VARCHAR))` (`src/ducklake/silver.py`) instead of `order_id` so multiple null-ID orders are preserved individually for Quarantine.
    *   Because `silver.py` inserts Python-parsed fields into fixed TEMP schemas, `quality.py` has no dataset-level check that blocks on missing upstream columns, and `sales_customers` is a passthrough entity in `PASSTHROUGH_ENTITIES` rather than an evaluated conditional entity in `ENTITY_RULE_SPECS`.
    *   `DuckDBSQLQualityGate` (`src/ducklake/quality.py`) additionally rejects `IS NULL` for `OCR_CONFIDENCE_RANGE` (`confidence`), `TG_NEGATIVE_REACTIONS` (`reaction_count`), `TELEMETRY_INVALID_STATUS` (`status_code`), and `TELEMETRY_NEGATIVE_LATENCY` (`latency_ms`), whereas the spec only lists numeric range predicates.
*   **`gold_ingestion_overview` aggregation scope and pre-rollback counts on `BLOCKED` batches**:
    *   `build_gold_marts` (`src/ducklake/gold.py`) maps each source to a single representative Silver entity in `source_silver_map` and `source_test_table` (`ocr_extractions`, `telegram_messages`, `database_rows`, `youtube_videos`, `surveys`, `telemetry_events`) instead of counting across all entities per source, computes `_is_test_artifact` and `MAX(_ingested_at)` from post-Quality-Gate valid Silver rows (excluding quarantined test artifacts), and falls back to current batch `ingested_at` when that table is empty (`max_ts or ingested_at`).
    *   In `LakehouseService.run_batch` (`src/ducklake/service.py`), `build_gold_marts` executes before `blocked_sources` deletes uncommitted Bronze files and decrements `total_bronze_counts`, and `mart_source_deps` sets `"gold_ingestion_overview": None`. On a `BLOCKED` run, `gold_ingestion_overview` is committed using pre-rollback Bronze and Silver counts.
*   **Partial `--full-refresh` scope, unindexed `quarantine/` dirs, and latest-only `.duckdb` quarantine export**:
    *   When `full_refresh=True` runs with a subset of `sources`, `LakehouseService._clear_for_full_refresh` (`src/ducklake/service.py`) clears only `watermarks`, `committed_bronze_batches`, and `bronze/<source>/` for the selected sources rather than resetting `silver/`, `gold/`, or `marts` pointers; even when refreshing all sources, prior `silver/v_*`, `gold/v_*`, and `quarantine/<entity>/v_*` directories remain on disk (with `silver`/`gold` pruned by `_prune_old_versions` and `quarantine/` retaining up to 10 directories unindexed from `manifest.quarantine_batches`).
    *   When `export_duckdb=True`, `LakehouseService.run_batch` (`src/ducklake/service.py`) passes `paths[-1]` per entity to `export_duckdb_snapshot`, so `quarantine.<entity>` in `lakehouse/ducklake.duckdb` contains only the latest quarantine batch instead of all committed quarantine batches.
*   **Additional `__init__.py` exports and test coverage/fixture deltas**: `src/ducklake/__init__.py` exports `ALLOWED_MARTS`, `ALLOWED_SOURCES`, and `LakehouseLockError` beyond the six exports listed in the spec; `tests/test_survey_extractor.py::test_api_extract_endpoint` still constructs `TestClient(app)` directly rather than taking a `client` fixture (relying on `autouse=True` `isolated_frontend_env` in `tests/conftest.py` instead of modifying the existing test file); and `tests/test_ducklake_pipeline.py::test_silver_dedup_and_edge_cases` seeds a YouTube Short with `duration_seconds=None` in `_seed_all_sources` without asserting YouTube Silver counts inside that test.
